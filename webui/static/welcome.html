What Nana is and how it works

What it is

One assistant, two tiers of model.

Most questions do not need the biggest model. Nana keeps the easy ones on a cheap tier and pays for a strong tier only when the question calls for it.

A chat that stays with you

Conversations are saved on this machine and can be searched. Replies stream in as they are written, and you can stop one part-way.

A router, not one model

Every message is scored before a model runs. Each reply shows which model answered and which route it took.

A workspace beside it

Notes, tasks, documents, memory, model comparison and agent runs live next to the chat. Some connections still need setting up.

How it works

What happens after you press send.

  1. 1

    You ask something

    Type a message as you would in any chat. Nana keeps the recent conversation as context, so follow-ups make sense.

  2. 2

    The router scores it

    Before any model runs, the router estimates whether the cheap tier is likely to be good enough. It looks at the length of the prompt and at signs of maths, code, logic or multi-part reasoning.

  3. 3

    Easy questions stay on the cheap tier

    If the score clears the threshold, the small model answers. In the local setup that model runs on your own machine, so there is no API charge.

  4. 4

    The answer is checked

    Nana looks at the cheap answer for signs it went wrong: nothing written, repeating itself, echoing the question, or hedging. A local answer also has to clear a confidence check. If it fails, the question is escalated.

  5. 5

    Hard questions go to the strong tier

    Prompts that score low, and cheap answers that fail the check, are sent to a larger model on Fireworks. Those requests are billable.

  6. 6

    Everything is accounted for

    You get one answer. Alongside it Nana records which model wrote it, the route it took, the tokens used and an estimated cost.
